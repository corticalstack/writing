Cache-aside reads: ask the cache first

How an app answers repeat reads without asking the database every time.

  1. The need. The same product page is read thousands of times a minute, and each read costs a database query.
  2. The gap. The database is the only place the data lives, so every read waits on it, even when nothing has changed.
  3. The fix. The app asks a cache first. On a miss it reads the database and stores the answer in the cache, so the next read is served from memory.
